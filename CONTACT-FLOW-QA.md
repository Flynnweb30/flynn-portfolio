# Contact Workflow QA

## Root cause fixed
The contact submission workflow was crashing before EmailJS was called because `Date.toLocaleString()` was invoked with `dateStyle` + `timeStyle` together with `timeZoneName`. That option combination is invalid in browsers implementing the Intl API and produced:

`TypeError: Invalid option : option`

The timestamp now uses explicit `month/day/year/hour/minute/timeZoneName` options, which are compatible with the browser Intl API.

## Submission flow
1. Visitor opens `/contact`.
2. The centralized `ContactSection` renders the inquiry form.
3. Browser validation checks required fields.
4. The delegated portfolio submit handler blocks the native navigation.
5. Honeypot is checked for basic spam protection.
6. EmailJS SDK is initialized or awaited.
7. Owner Notification `template_dhede6o` is sent to `va.flynnjames@gmail.com`.
8. User Confirmation `template_confirmation` is sent to the submitted `{{email}}` address.
9. Success event switches the React form to the confirmation state.
10. If owner delivery succeeds but confirmation fails, the visitor is told exactly what happened.

## Browser-only warning
`chrome-extension://invalid/` errors are generated by a browser extension or injected browser resource, not by this portfolio's source. The project contains no `chrome-extension://invalid` reference. Test the production site in an Incognito window with extensions disabled if that warning remains.

## Build verification
The environment used for this repair does not have the project's npm dependencies cached. `npm install` timed out and offline installation failed because packages were not cached, so a real Vite production bundle could not be executed here. Source-level checks, configuration checks, placeholder mapping, and archive integrity were performed.
